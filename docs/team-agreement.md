# 팀 합의와 결정 대기 항목

## 정해진 협업 방식

- 통합 기준은 `main`이다.
- 개인 포크 없이 팀 저장소의 작업 브랜치에서 같은 저장소의 `main`으로 PR을 제출한다.
- 팀원에게 작업 브랜치를 push할 수 있는 쓰기 권한이 필요하다. 관리자가 초대를 보내고 팀원이 수락해야 한다. 권한이 없으면 포크로 우회하지 않는다.
- 작업별 단기 브랜치는 기본적으로 Squash and merge한다.
- 비밀정보, 실제 데이터, 개인 설정과 임시 산출물을 저장소에 넣지 않는다.
- 공통 계약이나 담당 경계를 바꾸기 전 팀 합의를 확인한다.

## 아직 결정하지 않은 사항

| 항목 | 상태 | 결정 후 기록할 내용 |
| --- | --- | --- |
| 프로젝트 주제·목표 | 미정 | 사용자, 핵심 기능, 완료 기준 |
| 언어·프레임워크·DB | 미정 | 버전, 선정 이유, 설치 조건 |
| 팀원·담당 범위 | 미정 | 담당자, 기능·경로, 연계 담당자 |
| 공통 API 계약 | 미정 | 요청·응답, 인증, 오류 형식, 변경 절차 |
| 데이터 계약 | 미정 | 스키마, 마이그레이션, 샘플 데이터 기준 |
| 실행·검증 명령 | 미정 | 설치, 개발 실행, 빌드, 테스트 |
| 필수 리뷰·CI | 미정 | 필요한 리뷰 수와 검사 이름 |
| 운영·배포 | 미정 | 환경, 담당자, 승인·복구 절차 |

담당자 이름, API 경로, DB 구조, 개발 도구는 합의 전 임의로 배정하지 않는다. 결정되면 이 문서와 README·관련 코드·검증 설정을 같은 PR에서 갱신한다.

## 현재 검증 기준

- 문서 변경: 내용 일치, 저장소 내부 링크 유효성, `git diff --check` 확인
- 기본 CI: 전체 추적 파일의 공백 오류와 필수 문서 존재 확인
- 애플리케이션 빌드·테스트: 기술 스택과 코드가 없어 아직 구성하지 않음
- GitHub 쓰기 권한·보호 규칙·Squash 병합 옵션: 실제 설정은 별도 확인 대상이며 이 문서로 적용되지 않음

PR에서는 직접 실행한 결과와 CI 결과, 작성자 보고를 구분한다. 검사하지 못한 항목은 이유와 함께 남긴다.
